# Прошивки и конфигурации контроллеров Tibbo: написание, подбор Tibbit, проверка

Скилл для приложений TiOS на Tibbo BASIC (основной язык) и Tibbo C, собираемых в TIDE (или в VS Code с расширением Tibbo).
Источники (снимок октября 2026):
- **github.com/tibbotech** — автоматически извлечены API TiOS, платформы, библиотеки, каталог Tibbit (`tibbits.json`), примеры. Имена, сигнатуры и константы точные, сверяй код с ними.
- **docs.tibbo.com** — вручную выписаны питание, тайлы и сокеты, PoE, характеристики источников (power.md, tibbit-selection.md, `data/`). Остального (руководство TiOS, страницы всех Tibbit) в скилле нет: при сомнении читай нужную страницу через WebFetch (`https://docs.tibbo.com/tibbit_NN`, `/tps_common_power` и т.д.; из оболочки этот сайт обычно закрыт).

Если проект сгенерирован AppBlocks (в `global.tbh` есть `APP_ID`, в коде маркеры `'****boot****'`, процедуры `var_<X>_update/_set`),
это обычный TIDE-проект: проверяй его как любой другой, но правки лучше вносить в проект AppBlocks (скилл appblocks), иначе
они пропадут при следующей генерации.

**Windows:** скрипты запускай через `python` (или `python3`) из PowerShell, cmd или Git Bash; вывод всегда UTF-8, `PYTHONUTF8` не нужен.

## 0. Перед началом уточни контекст

Если что-то не указано, спроси одним сообщением, не больше трёх вопросов:
- **Платформа** точно как папка в Platforms: `TPP3W(G2)`, `TPP2W(G3)`, `DS1102W`, `EM2000W`, `WM2000`, `WS1102` и т.д. От неё зависят объекты, память, `PL_IO_NUM_*` и наличие TLS/Wi-Fi/BT.
- **Какие Tibbit стоят в каких слотах** (для TPS), что подключено к UART, **от чего питается** (стабилизированные 5 В, 12/24/48 В через какой Tibbit, PoE) и сколько градусов в шкафу.
- **Язык** (BASIC по умолчанию или C) и **версия библиотек** (`src_lib_ver` в .tpr), если используются библиотеки.

Если ответа нет, делай разумное допущение и пиши его первой строкой. Linux-устройства (LTPP3/LTPP3G2, NTIOS) — это не TiOS: там Linux, C/Node.js и объекты `lsock`/`lfd`. Не смешивай эти миры (см. github-map.md).

## 0.1. Аппаратная конфигурация: подбор Tibbit и питание

Любая задача, где фигурируют Tibbit, сокеты или питание (новый проект, подбор под ТЗ, ревью схемы, прошивка под конкретный набор Tibbit), начинается с проверки конфигурации скриптом, а не по памяти:

1. Подбор — по процедуре из `references/tibbit-selection.md` §3 (`tps_check.py find …` для кандидатов, `board …` для сокетов).
2. Питание — только по `references/power.md`. Главные ловушки: #09/#10 принимают **9–18 В** (не 24 В); на клеммы платы — только **стабилизированные 5 В**; #13/#14 без #12 не работают, а #12 сам ест 230 мА; #23 — только PoE-сокет и перемычки 1-2; модему нужен запас.
3. Собери `cfg.json` и запусти `python3 scripts/tps_check.py check cfg.json --svg map.svg`. Пока есть строки `[ОШИБКА]`, конфигурацию не выдавай; предупреждения либо исправь, либо объясни. Числа бюджета в ответе бери из вывода скрипта.
4. Покажи результат по правилам §7 (схема сокетов + бюджет питания + таблица).
5. Линии для прошивки (`PL_IO_NUM_*`, `ser.num`) бери из `tps_check.py board <плата>`, а не вычисляй в уме.

Если платы нет в `data/boards.json` (DS/EM/WM-модули, LTPP3), скрипт неприменим: проверь питание вручную по power.md и даташиту модуля и скажи, что автоматической проверки не было.

## 1. Язык Tibbo BASIC: факты, которые нельзя путать

Источники: docs.tibbo.com и грамматика из репозитория `tibbo-basic`.
- **Статическая память.** Кучи нет, вся RAM распределяется при компиляции. **Рекурсия и повторный вход запрещены.**
- **Типы:** `byte` (0..255), `char` (-128..127), `word` (0..65535), `short`/`integer` (±32767), `dword`, `long` (32 бита), `real`/`float` (IEEE 4 байта), `boolean`, `string`. Не все типы есть на всех платформах.
- **Строки:** по умолчанию вмещают 255 символов и занимают 257 байт RAM. Объявляй ёмкость явно: `dim s as string(32)`. Символы нумеруются с 1 (`mid(s,1,1)`). Встроенные функции перечислены в tios-api.md, раздел `## syscalls.tph`: `len left right mid instr(frompos, src, substr, num) asc chr val lval str stri lstr lstri hex lhex bin ftostr strtof ddstr ddval strgen strsum md5 sha1 random`, даты `daycount/year/month/date/weekday/mincount/hours/minutes`. Внимание: у `instr` 4 аргумента; `val` возвращает word, для 32 бит есть `lval`; `str` работает с word, для знаковых чисел нужен `stri`.
- **Массивы:** `dim a(5) as byte` — это 5 элементов с индексами 0..4. Многомерные: `dim t(5,2) as string(10)`. Структуры: `type ... end type`. Выход за границы ловит VM.
- **`dim` определяет, `declare` объявляет** то, что определено в другом файле (общие переменные и процедуры объявляй в `global.tbh`). Всё объявляется до использования. В `dim x,y as byte=5` значение 5 получит только `y`.
- **Литералы:** `&hFF`, `&b1010`, строки в `"..."`. Комментарий — `'`. Препроцессор: `#define #if #ifdef #ifndef #elif #else #endif #error`, `include "file"`, `includepp "file"` (подключает файл с `#define`, например settings.txt).
- **Управление:** `if ... then ... else if ... then ... else ... end if` (только `else if` через пробел, слитного `elseif` в грамматике нет), однострочный `if x then y`, `select case ... case else ... end select`, `for ... to ... step ... next`, `while ... wend`, `do ... loop [while|until]`, `exit sub|function|for|while|do`, `goto`.
- **Процедуры:** `sub name(byref s as string, n as byte)`, `function f() as word` (результат присваивается имени функции). Большие строки передавай `byref`: так не копируется 257 байт.
- `public` ничего не делает и оставлен для совместимости.
- **16-битная арифметика.** На 16-битных платформах (TPP2/TPP3 Gen1, EM1000, DS110x…) выражение считается в 16 битах, пока в нём нет 32-битной переменной: `(50000+60000)/10` = 4446. Тип платформы - platforms.md.
- Типы между `dim` и `declare` в разных файлах **не сверяются** ни компилятором, ни линкером - расхождение даёт порчу памяти. В BASIC массив в процедуру не передать - оберни в `type` и передай `byref`.

## 2. Модель исполнения TiOS

- Весь код выполняется в **обработчиках событий**, по одному, из очереди. Вход — `on_sys_init`. Периодика — `on_sys_timer`: по умолчанию 0,5 с, задаётся `sys.onsystimerperiod` в шагах по 10 мс.
- Основные события: `on_sock_data_arrival`, `on_sock_event(newstate, newstatesimple)`, `on_sock_data_sent`, `on_ser_data_arrival`, `on_ser_data_sent`, `on_button_pressed/released`, `on_net_link_change`, `on_wln_event`, `on_wln_task_complete`, `on_bt_event`, `on_kp`, `on_io_int`, `on_pat`, `on_beep`, `on_sys_dhcp_ok`. Точные сигнатуры смотри в tios-api.md.
- **Не блокируй.** Никаких `while sock.rxlen = 0 : wend`. Длинную логику делай конечным автоматом с переходами по событиям и таймеру, как `get_state` в HTTPS_GET.
- **`doevents`** обрабатывает накопленную очередь, потом возвращает управление. Обработчик, стоящий «на паузе», повторно не вызывается: событие того же типа выполнится после него. Используй только в долгих циклах (например, в `on_sys_init`).
- **Курсор канала:** `sock.num`, `ser.num`, `io.num`, `pat.channel`, `wln`… Почти все свойства относятся к выбранному каналу. При входе в событие сокета `sock.num` уже переключён на нужный сокет. После вызова чужих процедур или библиотек выставляй `.num` заново.
- **Буферы:** `sock/ser.rxbuffrq(n)` / `txbuffrq(n)` в страницах по 256 байт, затем **один** вызов `sys.buffalloc()` после всех запросов. Свободное место видно в `sys.freebuffpages`. На старых платформах страниц мало: смотри RAM в platforms.md.
- **Отладка:** `sys.debugprint(...)` работает в debug-сборке (`debug = on` в .tpr). В release исключения DIV0, OOR (выход за массив) и FPERR **не останавливают** программу - выполнение идёт дальше с неверным значением; делители и индексы проверяй сам. Release-.tpc грузится только на ту же платформу и ту же старшую версию TiOS.
- **Сторожевой таймер:** `sys.wdperiod` в шагах ≈10 мс (0–3000, по умолчанию 3000 ≈ 30 с); по умолчанию `sys.wdautoreset = ENABLED` — TiOS сама его сбрасывает, и зависание приложения он не ловит. Для настоящей защиты: `sys.wdautoreset = DISABLED`, `sys.wdenabled = YES`, `sys.wdreset` из живого пути; период ≈ вдвое больше интервала сброса.
- **Линии I/O:** запись `io.state` действует, только когда линия уже выход (`io.enabled = YES`), — сначала включай выход, потом пиши уровень. Сразу после включения выход обычно HIGH; если для нагрузки опасен и короткий LOW, это учитывай.

## 3. Библиотеки Tibbo — как подключать правильно

1. Файлы библиотеки добавь в проект (секции `[fileN]` в .tpr). Конфигурационные `#define` ставь в global.tbh **до** `include`. Для STG: `includepp "settings.txt"` (где лежат `STG_MAX_*`) ставь **перед** `include "settings.tbh"`, как в свежих тестах tibbotech/libraries; обратный порядок (как в старом CA-Test-STG-lib) держится на переопределении `#define` поверх значений по умолчанию.
2. Инициализируй из `on_sys_init`: `stg_start()`, `dhcp_start(...)`, `sock_get("SIG")` и т.д.
3. **Реализуй все `callback_*`**, которые объявляет библиотека. Пустое тело допустимо, без реализации проект не соберётся.
4. **Пробрасывай события:** `<lib>_proc_timer()` из `on_sys_timer`, `<lib>_proc_data()` из `on_sock_data_arrival`, `wln_proc_event()` из `on_wln_event` и т.д. Полная таблица в project-and-libs.md §3. Без этого библиотека молча не работает.
5. Сокеты распределяй через библиотеку `sock` (`sock_get("SIG")`), а не жёсткими номерами: DHCP, DNS и WLN тоже берут сокеты.
6. **Версии библиотек расходятся.** Последняя лежит в `tibbotech/libraries`, у TIDE своя в `Platforms/src/<src_lib_ver>/`, в примерах часто старые копии. Пример: `tbt13_init(YES)` в старом примере против `tbt13_init(signature, data_pin, clk_pin, byref tbt_channel, use_ssi)` в актуальной версии. Пиши под ту .tbh, которая реально в проекте.
7. **DHCP-библиотека сама IP не ставит**: в `callback_dhcp_ok` присвой `net.ip`, `net.netmask`, `net.gatewayip`.

## 4. Как работать

**Написание:**
1. Строка допущений: платформа, Tibbit по слотам, питание, язык, `src_lib_ver`. Если есть Tibbit — сначала §0.1.
2. Сверь каждое имя объекта, константы и библиотечной процедуры с references через Grep. Если имени нет в справочниках, не выдумывай: пиши `' TODO: проверить <имя> для <платформа> в docs.tibbo.com`.
3. Проект создавай файлами: `global.tbh`, `main.tbs`, `device.tbs` (колбэки), при необходимости `settings.txt` и `.tpr` по образцу из project-and-libs.md. Код длиннее пары десятков строк отдавай файлами, не в чат.
4. Приложи таблицу ресурсов: сокеты (подписи), порты, UART, линии I/O со слотами, страницы буферов против доступных, хранение настроек.
5. Пройди чек-лист §5 и честно отметь, что проверено статически, а что нет. **Никогда не утверждай, что код «скомпилируется»**: TIDE здесь недоступна.
6. Объясни, как проверить на железе: сборка в TIDE (debug), загрузка, что смотреть в выводе `sys.debugprint`, какие события должны прийти.

**Проверка чужого кода:** пройди §5 целиком. Отчёт по уровням «критично / важно / замечание», для каждого пункта укажи файл и процедуру, суть и исправленный фрагмент. Каждое использованное имя API сверь со справочниками: неверные имена и сигнатуры — критичная ошибка.

## 5. Чек-лист проверки прошивки

**Язык и память**
- [ ] Нет рекурсии и повторного входа (в том числе косвенного через `doevents`).
- [ ] У строк задана ёмкость; нет молчаливого обрезания при `getdata`, конкатенации, `mid`; большие строки передаются `byref`.
- [ ] Индексы массивов в пределах 0..N-1; нет переполнения `byte`/`word` в счётчиках; нет смешения знаковых и беззнаковых типов в сравнениях.
- [ ] На 16-битной платформе промежуточные результаты (умножение, сумма времён в мс) не выходят за 16 бит - в выражении есть `dword`/`long`.
- [ ] Глобальные `dim` и их `declare` в .tbh совпадают по типу и размеру (их никто не сверяет).
- [ ] Всё объявлено до использования; общие переменные заданы `dim` в одном .tbs и `declare` в .tbh.

**Событийная модель**
- [ ] Нет блокирующих циклов ожидания; долгие операции построены как конечный автомат.
- [ ] Обработчики короткие; `on_sys_timer` лёгкий; интервалы пересчитаны с учётом `sys.onsystimerperiod`.
- [ ] `doevents` есть только там, где он нужен, и не ломает общее состояние.

**Ресурсы**
- [ ] Все `buffrq` стоят до единственного `sys.buffalloc()`; сумма страниц влезает в платформу.
- [ ] Перед каждым обращением выставлен правильный `sock.num`/`ser.num`/`io.num`; события фильтруются по своему сокету.
- [ ] Сокеты выдаются через `sock_get`, номера не пересекаются с библиотеками.
- [ ] Используемые объекты есть на платформе (platforms.md); например, `tls`, `wln`, `bt`, `adc` есть не везде.

**Сеть**
- [ ] Обрабатываются link-down (`on_net_link_change`), смена или потеря IP (DHCP-колбэки), закрытие сокета (`on_sock_event`, `PL_SSTS_CLOSED`) и переподключение.
- [ ] Перед `setdata` проверяется `sock.txfree`; входящие данные разбираются с учётом фрагментации; есть таймаут на недособранное сообщение.
- [ ] `inconmode`/`localportlist`/`protocol`/`targetinterface` соответствуют задаче; для TLS хватает буферов и обработаны `PL_SST_EST_TLS` и `PL_SST_EST_TLS_FAILED`.

**Библиотеки**
- [ ] `#define` стоят до `include`; все `callback_*` реализованы; все `*_proc_*` проброшены из нужных событий.
- [ ] Сигнатуры совпадают с версией библиотеки в проекте.
- [ ] Результат `*_start()` проверяется.

**Железо, Tibbit, I/O**
- [ ] Конфигурация прогнана через `tps_check.py check` без ошибок (сокеты, UART/INT, разъёмы, PoE).
- [ ] Линии `PL_IO_NUM_*` соответствуют слотам и Tibbit (`tps_check.py board`); нет конфликта с UART/SSI/I2C.
- [ ] Линии -SDWN источников питания (#09/#10/#12/#23/#25/#33) прошивка не переводит в LOW случайно; -PF #33 обрабатывается, если нужен контроль пропадания питания.

## 6. Отладка по симптомам

- **Устройство «висит», не отвечает на сеть.** Ищи блокирующий цикл, слишком долгий обработчик или рекурсию.
- **Библиотека не работает (DHCP без IP, Wi-Fi без ассоциации, MQTT без подключения).** Не проброшены `*_proc_*`, не вызван `*_start`, или колбэк не применяет результат (DHCP).
- **Сокет не принимает подключения.** Проверь `inconmode`, `localportlist` (строка), `protocol`, что `buffalloc` вызван после `buffrq`, что сокет не занят библиотекой.
- **Данные обрезаются.** Ёмкость строки, `getdata(n)` с малым n, размер буфера, фрагментация TCP.
- **После вызова процедуры «чужой» сокет или порт.** Сбит `sock.num`/`ser.num`.
- **Не собирается.** Нет реализации `callback_*`, файл не добавлен в .tpr, сигнатура из другой версии библиотеки, объект отсутствует на платформе (`#define OBJECT_X` / `defines=` в .tpr).
- **Настройки теряются после перезагрузки.** Нет `stg_start()` в `on_sys_init`, тип `R` вместо `E` в settings.txt, ошибка STG (включи `STG_DEBUG_PRINT 1`).
- **Плата перезагружается при включении реле/модема, «прыгает» Ethernet.** Просадка 5 В: прогони бюджет `tps_check.py`, проверь запас и вход источника; для #33 смотри -PF.
- **АЦП #13/ЦАП #14 выдают мусор или ноль.** Нет #12 (±15 В) или он выключен по -SDWN.
- **Источник питания не включается.** Линия -SDWN в LOW (прошивка или сокет), вход вне диапазона, на #18 питание сразу на джек и клеммы.
- **TLS не устанавливается.** Мало буферов, неверный CA (нужен DER в ресурсах), имя хоста не совпадает с сертификатом, платформа без `tls`.
