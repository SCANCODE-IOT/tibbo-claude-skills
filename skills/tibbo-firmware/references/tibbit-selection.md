# Подбор Tibbit и раскладка по сокетам

Данные: `data/tibbits.json` (84 Tibbit: форма, линии, требования, питание, статус, теги RU/EN, ссылка на docs),
`data/boards.json` (сокеты TPP2/TPP3 всех поколений: линии, UART, INT, ADC, PoE, тайлы). Пересборка:
`python3 scripts/build_data.py data/tibbits.src.json`.

Команды:
```
python3 scripts/tps_check.py find "rs485 modbus"     # кандидаты по задаче (теги RU/EN)
python3 scripts/tps_check.py tibbit 61_1             # всё про один Tibbit
python3 scripts/tps_check.py board "TPP3W(G2)"        # возможности сокетов платы
python3 scripts/tps_check.py check cfg.json --svg map.svg   # проверка раскладки и питания
```

## 1. Геометрия (docs.tibbo.com: tibbit_sockets_tiles, tibbit_m2/h1/h2, tibbit_electrical)

- **Тайл** = 2 M-сокета + 2 C-сокета. На TPP: M — нечётные (S1, S3…), C — чётные (S2, S4…).
  Тайлы: S1–S4, S5–S8, … Разъём в C-сокете S_n+1 обслуживает модуль в M-сокете S_n.
- Варианты заполнения тайла: 2×M1 + 2×C1 · 1×M2 + 2×C1 · 2×M1 + 1×C2 · 2×H1 (и 1×H2 на весь тайл).
- **M1** — 1 M-сокет, 4 линии A–D. **M2** — оба M-сокета тайла (S_n и S_n+2), линии A–D первого + A–D второго.
- **C1** — 1 C-сокет. **C2** — оба C-сокета тайла (S_n+1 и S_n+3), подходит к одному M2 или к двум M1.
- **H1** — место M1+C1 (модуль и разъём в одном, соединены внутри). **H2** — место M2+C2 (весь тайл).
  Гибриды используют, когда связь M и C через плату нежелательна: высокое напряжение, ВЧ/радио.
- **S/T** — низкий/высокий. C1 по высоте равен M1T, C2 — M2T. Ограничений по высоте для корпусов TPB
  в документации нет — если важно, уточнить у Tibbo.
- SPI/I²C (объект `ssi`) назначаются на любые линии через `ssi.clkmap/dimap/domap`; UART и прерывания — только в определённых сокетах.

## 2. Возможности сокетов

| Плата | M-сокеты | UART (ser.num) | INT | Особые |
|---|---|---|---|---|
| TPP2 / TPP2(G2) / TPP2(G3) | S1–S11 нечётные | S1(0) S3(1) S5(2) S7(3) | все 6 | PoE S11 (M2: S9+S11); S13 — только #37 |
| TPP3 / TPP3(G2) / TPP3(G3) | S1–S27 нечётные | S1(0) S5(1) S9(2) S13(3) | S1–S15 | ADC S21 (G2/G3); S23 — только A,B; S25 — только A; S27 — без линий, PoE (M2: S25+S27); S29 — только #37 |

Номер PL_IO_NUM_* каждой линии — `tps_check.py board <плата>` или platforms.md. В .tph TPP3 есть опечатка:
PL_IO_NUM_38/39 подписаны «Socket 13», на деле это S15 A/B (S13 A/B — TX3/RX3).

## 3. Процедура подбора (выполняй по шагам)

1. **Требования списком**: интерфейсы (RS232/485, Modbus RTU, CAN…), дискретные входы (сухой контакт / 24 В /
   общий + или −), выходы (реле: ток и напряжение; SSR AC/DC; ОК 24 В NPN/PNP), аналог (0–10 В, ±10 В, 4–20 мА,
   скорость), температура (RTD, 1-Wire), связь (Ethernet, Wi-Fi, LTE, PoE), питание объекта (12/24/48 В, PoE),
   корпус (TPB2, TPB2L с экраном, TPB3), температура в шкафу.
2. **Кандидаты**: `find` по каждой функции. Отбрось `deprecated`/`not_recommended` (#48–#53, #56).
   Типовой выбор:
   - RS485 → #05 (M1S, нужен UART); RS232/422/485 универсальный → #02 (M2S); с гальваноразвязкой → #44 (H2).
   - Входы 24 В → #04_5…#04_8; сухой контакт → #54; наличие 220/110 В → #63 (H1).
   - Реле → #03 (слаботочные), #06 (силовые, M2T), SSR DC → #07, SSR AC → #15 (H1); ОК 24 В → #58/#59.
   - Аналог: ±10 В / 4–20 мА с развязкой → #61 (H2T, #61_1 ещё даёт 24 В для датчиков); простой АЦП → #13 (**+ #12**);
     ЦАП → #14 (**+ #12**); быстрый поток → #43 (нужен UART).
   - Температура: RTD → #22 (нужно INT); 1-Wire/DHT → #62; датчики-разъёмы #28–#36 ставятся с #00_3.
   - RTC с батарейкой → #42. LTE → #45 (H2, UART+INT), NB-IoT → #46.
3. **Питание**: выбери источник по напряжению объекта (power.md): 12 В → #09/#10 (или #33); 24/48 В → #25 или #33;
   PoE → #23; есть стабилизированные 5 В → клеммы платы. Добавь #12, если есть #13/#14.
4. **Раскладка**, в таком порядке приоритета:
   a. PoE-источник #23 — только в PoE-сокет.
   b. Всё, что `requires: serial` — в UART-сокеты (их 4). Тиббиты с `interrupt` — в сокеты с INT.
   c. M2/H2 — в начало тайла; учти, что они забирают весь ряд M (и C для H2).
   d. Остальное — в сокеты без особых возможностей (TPP3: S17–S21, S23 для двухлинейных, S25 — для источника
      без управления -SDWN).
   e. Разъёмы: в парный C-сокет (`mates` в каталоге), C2 #19/#20 — сразу на два модуля тайла.
5. **Проверка**: собери cfg.json и прогони `tps_check.py check cfg.json --svg map.svg`. Исправляй, пока нет ОШИБОК.
6. **Результат**: таблица «сокет → Tibbit → назначение → линии PL_IO_NUM_* / ser.num», бюджет питания, схема (SVG),
   спецификация к заказу (Tibbit, разъёмы, плата, корпус), что уточнить у Tibbo. Затем `#define` линий для прошивки.

## 4. Чего скрипт не проверяет (проверь сам)

- Электрические параметры нагрузки: ток реле, тип датчика, уровни сигналов, длина линий RS485.
- Высоту Tibbit под крышкой TPB2L/TPB3, тепловой режим в шкафу (кроме таблиц #23/#25).
- Совместимость Tibbit с конкретным поколением платы и версией библиотеки tbtNN (libraries.md).
- Пиковые токи модемов и пусковые токи нагрузок.
